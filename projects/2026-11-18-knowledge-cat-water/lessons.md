# บทเรียนตอน cat-water (ข้อเสนอแก้ไฟล์ร่วม ยังไม่ได้แก้เอง)

## ช้า: footage ใช้ ~44 นาที, ตัดต่อ ~24 นาที + เรนเดอร์ซ้ำ
1. **Wikimedia Commons API ติด 429 (retry-after 600 วิ) ตลอดเซสชัน** agent footage รอ/ลองซ้ำเป็นครึ่งชั่วโมง
   → make-clip ขั้น 4b: ใช้ **Openverse images API** แทน Wikimedia ตั้งแต่แรก (`https://api.openverse.org/v1/images/?q=...&license=cc0,by,by-sa,pdm` ได้ภาพ Wikimedia/Flickr/iNaturalist พร้อม creator/license/landing URL) ถ้า Wikimedia 429 ครั้งเดียว ห้ามรอ ข้ามไป Openverse ทันที
   → เพิ่มในตาราง "ปัญหาที่เจอแล้ว"
2. **ไม่มี PIXABAY_API_KEY ในเครื่องใหม่** เสียเวลารอตอนเริ่ม → ตั้งใน Environment variables ถาวร (`.env` ไม่ติดไปเซสชันใหม่)
3. **เฟรม 0 ไม่เห็นหน้าแมว/ไม่เห็นน้ำ** (footage ตัด 3 วิแรกของคลิป ซึ่งหัวลูกแมวมุดในแก้ว ช่วงที่เห็นหน้าอยู่ท้ายคลิป 14.05-14.85 วิ) reviewer จับได้ ต้องเรนเดอร์ใหม่ทั้งคลิป
   → make-clip ขั้น 4b: **ผู้กำกับเลือกช่วง hook เองก่อนตัดต่อ** ด้วย contact sheet ของคลิปเต็ม (`ffmpeg -vf "fps=1,scale=320:-1,drawtext=...pts...,tile=5x4"`) แล้วระบุ `media_start` ของช็อต hook ใน shots.json; footage ห้ามตัดคลิปเหลือแค่ช่วงต้นโดยไม่ดูทั้งคลิป
   → เช็กลิสต์ hook: เฟรม 0 ต้องเห็น "หน้า/ตาของสัตว์ + สิ่งที่คำถามพูดถึง (น้ำ)" ชัดตอนย่อเป็นภาพเล็ก
4. **ภาพนิ่ง Pixabay API ได้สูงสุด 1280 กว้าง** ครอป 9:16 เต็มจอเหลือ ~540px แตก → กฎ editor: ภาพนิ่ง <1920 ทำเป็น "การ์ดภาพ" กลางจอบนพื้นเบลอของภาพเดียวกัน + motion เสริม (ใช้ได้ดีตอนนี้)
5. **footage ไม่ตรงคำ** (เสือปลาในที่เลี้ยงไม่มีน้ำ แต่บทพูด "ดำน้ำจับปลา") → ผู้ใช้สั่ง: ช็อตที่ footage ไม่ครบ ใช้ motion graphic ช่วย (ผิวน้ำ/ปลาเด้งตรงคำ) → ใส่ในกฎ Motion เพิ่มของ style.md
6. **ภาพต่อจากชื่อพันธุ์ต้องเป็นพันธุ์นั้น** (ลูกแมวเล่นน้ำก๊อกตามหลัง "เตอร์กิชแวน" = ทำให้เข้าใจผิด) → เช็กลิสต์ storyboard
7. **ภาพต้องไม่หนักกว่าป้ายหลักฐาน** (ดินแตกระแหงกับข้อ ⚠️ "ถิ่นแห้งแล้ง") → เช็กลิสต์ reviewer/editor
