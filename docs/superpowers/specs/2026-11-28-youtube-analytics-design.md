# ระบบติดตามสถิติ YouTube (Analytics) — Design

วันที่: 2026-11-28 · สถานะ: ร่าง รอผู้ใช้อนุมัติ

## เจตนา (ทำไม)
ผู้ใช้อัปโหลดคลิปเองแล้วไม่มีทางรู้ว่าคลิปไหนได้ผล อยากได้ทั้ง (1) หน้าดูภาพรวม
(2) รู้ว่าอะไรได้ผลเพื่อเลือกหัวข้อต่อไป (3) รู้ว่าคนหลุดตรงไหนเพื่อแก้ hook
และให้ผลย้อนกลับเข้าสายพานทำคลิป (`make-clip`, `reality-check`)

## เป้าหมาย
- เก็บสถิติทุกคลิปของทั้ง 2 ช่อง (knowledge, football) อัตโนมัติ เป็นรายวัน เก็บประวัติ (snapshot) เพื่อดูกราฟตามเวลา
- แดชบอร์ดส่วนตัว: ภาพรวมช่อง, ตารางคลิป, กราฟวิวตามเวลา, เทียบ short vs long, กรองตามช่อง
- สรุปเชิงวิเคราะห์ (insight) รายสัปดาห์โดย AI ตามกฎ `reality-check` (ไม่สรุปเกินจากตัวอย่างน้อย)
- ผูกคลิปที่เผยแพร่กับ `projects/<...>/` เพื่อให้เห็นว่าหัวข้อ/ความยาว/hook แบบไหนได้ผล
- ระยะ 2: retention, เวลาดูเฉลี่ย, CTR ปก, แหล่งที่มาคนดู, Shorts viewed vs swiped away

## Non-goals
- ไม่อัปโหลด ไม่ตั้งเวลาโพสต์ ไม่ตอบคอมเมนต์ (ตาม CLAUDE.md)
- ไม่ติดตามช่องคู่แข่ง
- ไม่แก้ `channels/*/style.md` หรือ agent เองโดยอัตโนมัติ (เสนอผ่านรายงาน ผู้ใช้อนุมัติ)

## Anti-goals (ถือว่าล้มเหลวแม้ทำงานได้)
- สถิติช่อง, token, key หลุดเข้า repo (repo เป็น public)
- AI สรุปว่า "แบบนี้ได้ผล" จากคลิปไม่กี่ตัว
- ระบบต้องให้ผู้ใช้ดูแลเซิร์ฟเวอร์เอง

## ข้อจำกัด
- repo public: เก็บเฉพาะโค้ด/เอกสาร ห้ามเก็บตัวเลขสถิติหรือความลับ
- เซสชันคลาวด์ชั่วคราว: ที่เก็บข้อมูลต้องอยู่นอก container
- YouTube Data API: ใช้ API key (ตัวเลขสาธารณะ: วิว ไลก์ คอมเมนต์) · Analytics API: ต้อง OAuth ของเจ้าของช่อง ผู้ใช้สร้าง credential ใน Google Cloud เอง
- โควตา Data API 10,000 หน่วย/วัน (เรียกอ่านสถิติถูกมาก)

## แนวทางที่พิจารณา
- A: สคริปต์ + รายงาน md ในเครื่อง — ง่ายสุด แต่ไม่มีหน้าดู
- **B (ผู้ใช้เลือก ตามที่แนะนำ):** สคริปต์เก็บข้อมูล + แดชบอร์ด Artifact (ส่วนตัว) พร้อมฐานข้อมูลของ Artifact
- C: เว็บโฮสต์เอง — ภาระดูแลและค่าใช้จ่ายสูงเกินสำหรับช่องที่ยังเล็ก

## การออกแบบ (ตามที่ตัดสินใจ)
1. **ตัวเก็บข้อมูล** `tools/yt_stats.py` (Python, ไม่มี dependency หนัก): ดึงรายการวิดีโอจาก uploads playlist ของแต่ละช่อง แล้วดึงสถิติเป็น snapshot รายวัน
2. **ที่เก็บ**: ฐานข้อมูลของ Artifact (คอลเลกชัน videos, snapshots, insights) ไม่อยู่ใน repo
3. **รันอัตโนมัติ**: scheduled task รายวัน เปิดเซสชันสั้นๆ รันตัวเก็บแล้วเขียนลง DB
4. **แดชบอร์ด**: Artifact ส่วนตัว อ่านจาก DB
5. **Insight รายสัปดาห์**: scheduled task อ่าน DB ใช้กฎ `reality-check` เขียนสรุป (พร้อมระบุขนาดตัวอย่างและความมั่นใจ) ลง DB และแสดงบนแดชบอร์ด
6. **วนกลับสายพาน**: บทเรียนที่ไม่มีตัวเลขช่อง (เช่น "hook แบบถามคำถามคงอยู่ได้ดีกว่า") เสนอให้ผู้ใช้อนุมัติก่อนเพิ่มลง `docs/analytics-learnings.md` ที่ `make-clip` อ่านตอนเลือกหัวข้อ

## แผนเป็นระยะ
- ระยะ 1: API key, ตัวเลขสาธารณะ, แดชบอร์ด, insight พื้นฐาน
- ระยะ 2: OAuth + Analytics API (retention ฯลฯ) หลังผู้ใช้ตั้ง credential

## ปล่อยให้ผู้สร้างตัดสิน
โครงสร้างข้อมูลละเอียด, ไลบรารีกราฟ, วิธีแมตช์วิดีโอกับโฟลเดอร์ project (ข้อเสนอ: จับคู่ชื่อเรื่องกับ `upload.md` อัตโนมัติ และให้ผู้ใช้แก้เองได้), วิธีส่งความลับ (API key/OAuth refresh token) เข้า scheduled task โดยไม่ลง repo

## การตัดสินใจเพิ่มเติม (จากผู้ตรวจ — เป็นข้อเสนอของผู้ออกแบบ ผู้ใช้ยังไม่ได้ยืนยัน)
- **เขียนลง DB**: สคริปต์ไม่เขียน DB เอง แต่พิมพ์ผลเป็น JSON แล้วเซสชันของ scheduled task เขียนลง Artifact DB ด้วย ArtifactData (แบบ batch) ต้องยืนยันตอนวางแผนว่าเซสชันที่ตั้งเวลาเข้าถึงเครื่องมือและ Artifact นี้ได้ ถ้าไม่ได้ ทางสำรองคือให้ผู้ใช้กดรันเซสชันเก็บข้อมูลเอง
- **ความลับ**: เก็บผ่าน request_credential (proxy แนบ key ให้ ส่ง key ผ่าน header `x-goog-api-key`) ต้องยืนยันว่า environment อนุญาตโฮสต์ `www.googleapis.com` / `youtube.googleapis.com` ถ้าไม่ ให้ขอเพิ่มผ่าน update_environment
- **การเข้าถึง**: แดชบอร์ดส่วนตัวของเจ้าของเท่านั้น (ไม่แชร์)
- **เกณฑ์ตัวอย่างขั้นต่ำ**: insight เปรียบเทียบรูปแบบ/หัวข้อต้องมีอย่างน้อย 10 คลิปต่อกลุ่มและแต่ละคลิปอายุ ≥7 วัน ไม่ถึงให้ระบุว่า "ยังสรุปไม่ได้" และแสดงเฉพาะตัวเลขดิบ
- **ต้องการจากผู้ใช้ก่อนเริ่มระยะ 1**: URL/handle ของทั้ง 2 ช่อง และ API key ที่สร้างใน Google Cloud (เปิด YouTube Data API v3)
